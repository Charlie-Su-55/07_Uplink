# LLR mechanism controls and independent confirmation

This batch separates conditional scaling, residual/CE features, model capacity and noise-level calibration. It trains only the new small EP5 LLR readouts, freezes validation-selected checkpoints, and evaluates the complete predefined independent confirmation budget. Graph is inactive in this batch.

## Actual starting evidence

The immutable archive `docs/experiment_snapshots/cachedscale_20261008_dev1/` contains `summary.csv`, `decision_summary.json` and `training_manifest.json`. On its old 64-channel development set, aggregated over three Eb/N0 points and 3072 TBs, raw EP5 has 285 block errors; the train24 global/per-bit constants have 268/265. The three 1000-step full-MLP best checkpoints have 257/256/255 block errors. Graph best has 256/257/253, with mixed paired directions; this is not evidence of a consistent Graph advantage. The former four-input MLP ablation has 259/262/260 errors and a different parameter count, motivating the matched-capacity masks below.

The source tensors remain at `data/cache/paper_soft_output_dev/softdev_20261008_dev1/`. Missing or corrupt training cache stops preflight; there is no rebuilding fallback. The three frozen reference weights remain under `ckp/cached_llr_scaling/cachedscale_20261008_dev1/mlp/seed_42/`, `seed_43/` and `seed_44/`, each `best.pth` at the archived actual step 1000. Their hashes, original normalization and provenance are checked; they are inference references, not initialization for the new models.

Historical cache identity and new algorithm/configuration/runtime identity are recorded separately. Source manifests are never rewritten to pretend they were generated by new code. Read-only preflight checks every existing source tensor's hash/schema, including development records; their labels or features do not enter training, normalization or model selection. Completion checking compares saved data/algorithm/environment identities; a documentation-only commit does not invalidate an otherwise identical run.

## Fixed training and controls

All defaults are in `configs/evaluation/llr_mechanism_controls.yaml`.

| Setting | Value |
|---|---|
| Training channels | `81000000`–`81000023`, 24 original calibration channels |
| Validation channels | `81000024`–`81000031`, remaining 8 calibration channels |
| Training/validation Eb/N0 | `[-12, -10.5, -9]` dB; each seed keeps all three points |
| Input nodes | Posterior mean real/imaginary, log posterior variance, log Gram diagonal, log posterior residual, eta |
| Preprocessing | Existing fixed clipping/epsilon rules; normalization fitted only on the 24 training channels |
| Training seeds | `42, 43, 44`; fresh alpha=1 initialization |
| Training budget | 3000 steps, 256 RE/step, validation every 100 steps |
| Optimizer | AdamW, lr `1e-3`, weight decay `1e-4`, gradient norm clip `1.0` |
| Selection | Minimum validation coded-bit BCE only; save both best and last |
| Output | Four positive scales per RE/UE, shared weights across UE identities |
| Bounds | `alpha=exp(clamp(log_scale,log(0.05),log(8)))`; fixed throughout |

| New candidate | Input treatment | Trainable parameters |
|---|---|---:|
| `full_mlp` | All six normalized features; two width-32 SiLU hidden layers | 1412 |
| `mlp_without_residual` | Set the normalized residual coordinate to zero | 1412 |
| `mlp_without_eta` | Set the normalized eta coordinate to zero | 1412 |
| `mlp_without_both` | Set both normalized coordinates to zero | 1412 |
| `affine_all_features` | Shared affine map from all six normalized features to four log scales | 28 |

The masks apply after train-only normalization and retain the same six-input MLP architecture and parameter count. Original LLR sign, ordering and values are preserved before multiplying by positive scales; no bias or LLR clipping is added. True H, true noise, payload/coded labels, CRC/error outcomes, channel IDs and UE IDs are absent from inference features. Labels only supply losses and metrics.

Three train24 constant controls accompany every model: one pooled global alpha, four pooled bit-position alphas, and four noise-conditioned alphas at each of the three training Eb/N0 points (12 fitted values). Each minimizes training coded-bit BCE within `[0.05,8]`. The noise-conditioned control interpolates log alpha linearly against the actual log N0, with endpoint hold outside the training range; it never fits or selects a new scale on confirmation data.

## Independent confirmation

The fixed budget is 512 channel seeds and seven points `[-12,-11.5,-11,-10.5,-10,-9.5,-9]` dB: 3584 channel/EbNo observations, 57,344 TBs per receiver. The actual initial audited plan is `90000000`–`90000511`, selected after excluding 713 archived/runtime seed values covering historical training, validation, CE calibration, calibration/development and prior evaluation records. Preflight saves the final explicit lists and exclusion evidence. Repeated Eb/N0 points and repeated trained models do not multiply the 512 independent channel count.

Each realization passes once through the original normalized UMa Mode-B transmitter, practical CE and CE-aware front end. All methods share the same bits, pilots, data RE, Hhat, err_var and N0. The physical contract remains 16 UEs with one stream each, 256 Rx, four physical Tx antennas per UE with rank-one equal-gain mapping, no fractional power control/interference, fixed pilot symbols 2/11, 2304 data RE, Qm=4, G=9216, k=3104, CP=14 and the original `ebnodb2no()` accounting. CE uncertainty reaches native LMMSE and the established diagonal-whitened EP path. Full codewords are decoded; RE chunks only bound computation.

The primary receiver pool contains exactly 23 entries:

- Native Sionna LMMSE and raw EP5.
- `global_train24`, `per_bit_train24` and `noise_per_bit_train24`.
- Five new candidates × three training seeds, using only their preselected best checkpoints.
- Three frozen 1000-step MLP best references, paired by training seed.

All new last checkpoints are saved for traceability but excluded from primary confirmation. Training finishes and checkpoint choices freeze before the first fresh confirmation channel. The evaluator neither stops early for performance nor refits, selects a favorable training seed, expands the Eb/N0 range or feeds confirmation results back into training.

## One-command server runs

Use the existing Sionna 2.0.1 / archived torch 2.11.0 server environment from the repository root. The runner uses the active `python`, or an existing interpreter selected by `PYTHON`. Matplotlib must already be available for vector figures; dependencies are not installed or upgraded.

```bash
bash evaluation/run_llr_mechanism_controls_batch.sh smoke --run-id mechanism_20261008_smoke1
```

Smoke uses two optimizer steps, training seed 42, the first old training seed at all three training Eb/N0 points, and the first old validation seed `81000024` at -10.5 dB for full-codeword decoding. Its fits use only this declared training subset. It evaluates 13 receivers (five new seed-42 readouts, five baselines and all three frozen references) on old validation data, and generates no fresh confirmation channels.

Before running an updated version on the server, verify the branch and pull with fast-forward only:

```bash
test "$(git branch --show-current)" = "refactor/sionna-standard-ebno" && git pull --ff-only --no-tags origin refactor/sionna-standard-ebno
```

One background command runs the entire fixed batch; the launcher log refuses overwrite:

```bash
mkdir -p logs/llr_mechanism_controls && (set -o noclobber; exec nohup bash evaluation/run_llr_mechanism_controls_batch.sh confirmation --run-id mechanism_20261008_confirm1 < /dev/null > logs/llr_mechanism_controls/mechanism_20261008_confirm1.launcher.log 2>&1) &
```

The sequence is preflight → new lightweight tests → separate old-data smoke under `mechanism_20261008_confirm1_smoke` → smoke decode/completion check → full fitting/training → independent confirmation → report/figures → completion verification. Failures preserve the stage and actual pipeline exit code and stop later stages.

```bash
tail -f logs/llr_mechanism_controls/mechanism_20261008_confirm1/runner.log
cat logs/llr_mechanism_controls/mechanism_20261008_confirm1/runner_status.txt
cat logs/llr_mechanism_controls/mechanism_20261008_confirm1/stages.tsv
python -m evaluation.evaluate_llr_mechanism_controls --run-id mechanism_20261008_confirm1 --mode confirmation --check-complete
```

Completion requires runner `state=complete`/`exit_code=0`, the fixed complete case/method budget, complete summary, checked hashes and all six vector figures. Run `--check-complete` in the original server environment; it verifies artifacts without new GPU inference or decoding. Logs include PID, start time, elapsed time and per-stage status. Existing output directories are rejected by default. Explicit `--reuse-complete` accepts only matching complete artifacts; it does not authorize partial training/results overwrite or a cache-generation fallback. No other GPU process is killed.

## Statistics, targets and output files

Per-case records retain compact per-UE errors/CRC/outcomes, sufficient for paired rescue/harm and channel-level bootstrap. Large y/H, complete LLR tensors, A1 candidates and confirmation `.pt` replay packages are not saved. Original training caches and historical archives remain read-only.

Outputs live under `ckp/llr_mechanism_controls/<run-id>/`, `results/llr_mechanism_controls/<run-id>/` and `logs/llr_mechanism_controls/<run-id>/`:

- Training `manifest.json` records all train-only fits, normalization, identities, steps and best/last hashes; candidate checkpoints stay in their candidate/seed directories.
- Results `summary.json`, `summary.csv` and `channels.jsonl` give full-TB BLER, payload BER/CRC, coded BER/BCE, fixed-scale GMI proxy, per-channel/UE outcomes, scale saturation and provenance.
- `decision_summary.json` compares full MLP with the three constant controls, each matched mask, all-feature affine and same-seed frozen MLP, pooled and at every measured Eb/N0.
- `targets.json` reports targets 0.1 and 0.05 for every training seed and the seed-mean curves; `parameters_added_time.csv` reports parameter counts and measured added scale/decode time.
- `plots/bler_curves.{pdf,svg}`, `plots/feature_ablation.{pdf,svg}` and `plots/parameters_added_time.{pdf,svg}` are vector artifacts. Curves show all three training seeds separately and their mean/range; zero observed BLER uses a labelled display floor only.

Paired differences are **candidate minus baseline**; negative delta BLER/BCE favors the candidate. Percentile intervals resample whole channel seeds, moving all UEs and Eb/N0 observations together. Rescue/harm is paired by channel, Eb/N0 and UE. Training-seed variation is shown separately; three models do not triple independent samples. Multiple predeclared comparisons have no multiplicity correction, and lower BCE is not treated as proof of lower BLER.

Target interpolation is predeclared as linear Eb/N0 against log10(BLER), using only adjacent measured points that bracket the target or an exact measured target. All brackets are returned. Any globally nonmonotonic curve, multiple crossing/plateau, absent bracket or zero endpoint incompatible with the logarithm remains `unresolved`; there is no extrapolation or favorable crossing selection. A dB gain is reported only when both curves resolve, as **baseline required Eb/N0 minus candidate required Eb/N0**. Positive means lower required Eb/N0 for the candidate. Training-seed means are averaged curves, not a selected best seed.

Scale distributions aggregate fixed bins `[0.05,0.1,0.25,0.5,0.75,1,1.5,2,4,8]` both pooled and at each measured point; bins are left-closed/right-open except the final closed bin. Counts/fractions and lower/upper-bound saturation remain separate. Parameter/time tables also state effective input counts 6/5/5/4/6 for the five new candidates, with all MLP nominal inputs still six.

Timing separates the once-per-realization shared PHY, CE, native equalization, EP, front-end and feature work from each readout's `scale_forward_seconds` and `decode_seconds`. Added scale timings cannot support a complete-receiver speedup claim. Per-model training elapsed time includes validation and checkpoint writing. Estimates printed while running derive only from completed measured cases; no GPU performance or total runtime is asserted before execution.
