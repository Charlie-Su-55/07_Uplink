## 1. Critical bugs

### C1 — Fixed-BLER interpolation can extrapolate after flooring zero counts

- File/function: `evaluation/evaluate_mcs_bler.py:609`, `interpolate_snr_at_bler`.
- Reproduction: SNR `[0,1]`, BLER `[0.2,0]`, ten blocks per point, target `0.01` returns `2.160964` dB, outside the measured interval. Raw BLER brackets the target, but the `0.5/N` floor does not.
- A single observation exactly equal to target returns `None`, since only adjacent pairs are examined.
- Risk: invalid fixed-BLER numbers for low targets/small samples; the default target 0.1 with 500 channels is not shown to be affected by this particular boundary error.
- Minimal fix: validate inputs, handle exact points first, require a bracket also after the log-domain floor, and return an explicit unresolved result when resolution is insufficient. Never extrapolate.
- GPU required: no for arithmetic; yes for end-to-end evaluator smoke.

No confirmed default-path physical-model bug was found by static inspection. Practical detector inputs are explicitly `h_hat_lmmse + ruu_hat`; True-H is used for diagnostics or forward signal generation. Ruu already includes thermal noise; detector whitening does not add it again. All hard decisions use `llr > 0`. These are code findings, not proof of GPU runtime correctness.

## 4. Scientific-risk issues

- **Practical/oracle:** True-H in coded payload injection is a transmitter/channel forward-model operation, not a detector input. The legacy alias is an avoidable future leakage hazard. CE additionally assumes known simulator thermal-noise variance (`data/dataset.py:55`), so “practical” must state this assumption.
- **DMRS:** `data/dataset.py:20` enables `protect_dmrs=True`; `data/link/interference.py:56` zeros all external interference on DMRS symbols. Pilots have amplitude `sqrt(16)` (`data/link/dmrs.py:10`). This is protected, power-boosted, interleaved-comb DMRS; do not describe the simulation as arbitrary pilot interference or full standards-compliant PUSCH mapping. Preserve these existing assumptions pending research decisions.
- **Pairing:** A single sample/bit payload/estimated H/R feeds all detectors at each BER or BLER evaluation point. Training resets physical seeds per step after model construction and uses a separate seeded SNR schedule. Formal sweeps use a common seed and channel count per SNR. Verify actual tensors on the pinned server stack; static seeding is not a runtime determinism guarantee.
- **Train/validation/test:** Validation uses `seed+2000`, training uses `seed*100000+step`; evaluation uses separate defaults. Users can still select overlapping seeds. Record actual seeds and run configuration. Covariance cache uses a separately generated dataset (default seed 1701).
- **Checkpoint:** Architecture builders agree on GT 4 layers / DETR 3 layers, 128 dimensions, 8 heads, FFN 256, dropout .05 and five EP iterations. Both loaders are strict. Parameter counts depend on Qm. Real checkpoint provenance cannot be certified without the server artifacts.
- **Architecture comparison:** DETR includes 12 node scalars plus 7 pair features per stream and learned stream identity; GT uses 6 node scalars plus 6 edge features. This is a comparison of two complete refiners, not an isolated attention-architecture ablation. Do not change the models to force a GT advantage.
- **BLER uncertainty:** All 16 UE blocks within one channel share the channel/interference environment. BER uses channel-level paired bootstrap correctly. BLER saves only aggregate counts in the baseline, which is insufficient to recover channel-cluster uncertainty. Save channel counts; do not attach independent-bit/binomial precision or interpret a 0.005dB difference as significant.
- **Interpolation:** Log-BLER interpolation is only an estimate within sampled support. Warn on unresolved and nonmonotone curves; coarse-only estimates must remain labeled diagnostic. No extrapolation or precision claim beyond sample/grid support.
- **Coded SNR:** `build_coded_sample` retains interference/noise from an uncoded draw after replacing desired data. `UplinkLink.noise_variance` calibrated that noise using the original finite-sample clean data power. All detectors are paired, but the injected codeword's realized SNR can differ. Measure this on server before interpreting SNR labels more precisely; do not silently change the existing physical experiment.
- **CE cache:** The cache path is fixed, not tracked, and only dimensions/power are validated. Keep the exact server cache and record its hash. Do not regenerate it silently; dimension compatibility alone does not prove matching topology/power statistics.
- **Environment:** Local Python 3.12, torch 2.6.0, numpy 1.26.1, Sionna 0.15.1, no PyYAML. `sionna.phy` import fails. No environment reinstall or local 256Rx simulation is authorized. Server integration requires the stated torch 2.11 / Sionna 2.0.1 environment.

Sionna behavior checked against the pinned upstream source: [2.0.1 random seed reset](https://github.com/NVlabs/sionna/blob/v2.0.1/src/sionna/phy/config.py), [channel-estimator shapes/noise contract](https://github.com/NVlabs/sionna/blob/v2.0.1/src/sionna/phy/ofdm/channel_estimation.py), [TB decoder](https://github.com/NVlabs/sionna/blob/v2.0.1/src/sionna/phy/nr/tb_decoder.py). No source was substituted into the local installed environment.
